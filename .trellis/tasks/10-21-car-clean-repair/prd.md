# 车型参数清洗完整性与存量补清洗

## Goal

修复车型详情页“有原始参数但清洗参数为空”的空白问题，补齐存量清洗数据，并建立清洗完整性与成功口径，避免再次出现 `SUCCESS` 但详情/RAG 无参数的情况。

## Background（2026-10-21 生产只读核对）

- 57 台车型中：43 台有原始参数；仅 8 台有清洗参数；**35 台有原始参数但 `car_param_clean` 为空**。
- 典型：id=14「第二代元PLUS智驾版」有 5 个版本、16 个参数组、202 条原始参数，但清洗 0 条；`/car/14` 详情页表格全空。
- 详情页只渲染 `groups[].cleans`，没有回退 `params`；清洗缺失时页面静默空白。
- `CarChunkService.buildParamGroupChunks` 对 `cleans.isEmpty()` 的分组直接跳过；清洗缺失也会让这些车型没有参数 RAG 块。
- 旧「图片补入库」只处理图片，不做清洗，却会写 `SUCCESS`/`lastSyncAt`；成功口径未校验清洗覆盖。
- `cleanForModel` 先删除旧清洗再读参数；参数为空时会清空已有清洗（当前全量预检挡住了，但缺少通用保护）。
- 另：8 台真空壳（7 台有版本无参数组；大汉EV 无版本/参数）需安全全量同步；11 台官网 `EMPTY` 保持不动。

## Requirements

### R1 详情页兜底（P0）

- `cleans` 为空但 `params` 非空时，详情页展示原始参数，并标注「原始参数/待清洗」。
- 不得把原始参数伪装成已清洗数据；表头/类型列明确区分。
- 无参数时才显示空态。

### R2 存量补清洗（P0）

- 提供 ADMIN 运维能力：对“有原始参数但清洗为 0”的车型，基于库内参数重跑 `cleanForModel`，不重新请求官网。
- 支持单车型补清洗和全量缺失补清洗；返回处理数/跳过/失败明细。
- 补清洗幂等；重复执行不重复插入；不触碰版本/参数/图片/向量原始数据。

### R3 清洗安全与完整性契约（P0/P1）

- `cleanForModel` 在参数为空/无有效值时**不得删除已有清洗结果**。
- 全量同步在清洗后校验覆盖：清洗行数 > 0；为 0 时不得写完整 `SUCCESS`（至少 `PARTIAL` 并写 note）。
- 图片补入库不得单独把“无参数/无清洗”的车标成完整 `SUCCESS`。
- 清洗版本对齐保持现有下标语义，但补充长度/空值校验和日志；异常不得静默成功。

### R4 空壳与 EMPTY（P0）

- 7 台有版本无参数 + 大汉EV 执行安全全量同步（官网可用时）；失败则保留旧数据并标记。
- 11 台 `source_state=EMPTY` 不做全量同步，不删除旧参数/清洗。

## Acceptance Criteria

- [x] `/car/14` 在补清洗后展示 16 个分组、参数表格有值；清洗数量 > 0。
- [x] 35 台“有参数无清洗”全部补齐或逐台记录失败；补清洗不改变版本/参数数量、封面和向量。
- [x] 详情页在清洗缺失但原始参数存在时不再空白，显示「原始参数/待清洗」。
- [x] `car_param_clean` 为空时同步状态不得为完整 `SUCCESS`（单测覆盖）。
- [x] `cleanForModel` 在参数为空时不删除旧清洗（单测覆盖）。
- [x] 8 台空壳中的 7 台补齐参数组/清洗（官网可用时）；大汉EV 有版本/参数或明确失败；11 台 EMPTY 不变。
- [x] `mvn test`、`npm run build`、Playwright smoke 通过；规格文档同步。

- 对 11 台官网 EMPTY 车型强行补参数。
