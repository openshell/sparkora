# 智能建议候选卡横排布局优化

## Goal

配图抽屉宽度不变,智能建议候选从「两列小卡」改为「单列横排卡」,消除 420px 抽屉下信息挤爆的展示问题。

## 背景(问题定位)

抽屉固定 `size="420px"`(PreviewImageDrawer.vue:2),用户明示**不能加宽**——抽屉是 overlay,打开时已遮挡预览画布一半,再宽会完全挡住。当前建议组 `sug-grid` 两列栅格,每卡仅 ~175px,标题/相关度/标签/「插入到此段」挤作一团,展示不友好。

## 方案(用户已选定 B1)

建议组内候选改**单列横排卡**:

- 左:缩略图固定宽 ~100px(4:3,`fit=cover`,大图预览保留)
- 右:信息列——相关度 + 「已采用」标记一行;标签一行(≤2 个全显,超出折叠为 `+N`);「插入到此段」按钮
- 组头(标题/全部采用/忽略此段)与锚点文字保留:锚点文案 2 行收为 **1 行省略**(原生 `title` 提示全文即可)

## Requirements

- **R1 横排卡布局**:仅动「智能建议」tab 的候选卡模板与样式;缩略图左 ~100px + 信息右侧;事件接线(`onAdoptOne`/`onAdoptGroup`/`onDismissGroup`)、busy、大图预览、`已采用` 标记行为零变化。
- **R2 内容收纳**:锚点文案 1 行省略;标签最多显 2 个 + `+N` 折叠(≤2 时全显)。
- **R3 范围红线**:抽屉 `size="420px"` 不变;图库 tab(三列网格)、AI 生图 tab、其他场景不动;不改 composable 逻辑与接口契约(纯前端模板/样式);不新增保存通道。
- **R4 控件密度**:沿用项目 token(`--control-h-sm` 等),缩略图/标签行高紧凑;不引新依赖。

## Acceptance Criteria

- [ ] 真机:建议生成后,组内每张候选为横排卡——缩略图左、相关度/标签/按钮右侧完整可见,无换行挤压;锚点文案单行省略
- [ ] 真机:标签 >2 个时折叠为 `+N`,鼠标悬停可看(或至少视觉上不撑爆行)
- [ ] 图库 tab、AI 生图 tab 零回归(样式未被误伤,npm build 通过)
- [ ] `npm run build` 通过
- [ ] `docs/spec/image.md` §8 智能建议 UI 描述若无布局级描述则无需改;若有则同步

## Non-goals

- 不加宽抽屉(用户否决:遮挡预览画布)
- 不做侧栏面板替代抽屉的页面结构改版(B2 行内极简也已否决,标签可见性优先)
- 不动建议生成/采纳/忽略任何链路逻辑(纯展示层)
