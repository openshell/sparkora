# prd.md — BYD Agent Windows 一键控制面板

> 父任务：`10-16-byd-dynasty-local-push`

## Goal

把现有 `python .\byd_local_agent.py run` 命令行操作封装成 Windows 一键控制面板，让非开发用户能双击启动、查看状态并安全停止本机 Agent。

## Requirements

### R1 一键启动

- 提供可直接双击的 Windows 启动入口。
- 启动时若 Agent 未运行，自动在后台启动。
- 不弹出 Python 控制台窗口。
- Agent 输出写入本地日志。

### R2 状态可见

控制面板至少显示：

- Agent 进程运行状态与 PID；
- 微信相关进程是否已退出；
- 最近一次预检结果及失败原因；
- 最近日志。

### R3 快捷操作

提供以下按钮：

- 启动 Agent；
- 停止 Agent；
- 重新预检；
- 打开配置；
- 打开日志；
- 打开发布页；
- 退出控制面板（不停止 Agent）。

### R4 安全停止

- 停止操作必须通过停止标记请求 Agent 在调度周期边界退出。
- 正在执行 MMKV 写入时不得强杀进程。
- 控制面板等待一段时间后若仍在运行，应提示“任务完成后退出”。

### R5 兼容与安全

- 仅使用 Python 标准库，不新增部署依赖。
- 不读取或展示 Token、签名密钥等敏感值。
- 不修改 Server API、任务 payload 或 MMKV 写入逻辑。

## Acceptance Criteria

- [ ] AC-1 双击启动入口可在无控制台窗口的情况下打开控制面板。
- [ ] AC-2 控制面板可自动启动 Agent 并发现已运行进程。
- [ ] AC-3 状态区正确展示 Agent、微信和预检信息。
- [ ] AC-4 停止操作通过停止标记执行，不强杀正在写的任务。
- [ ] AC-5 配置、日志、发布页入口可用。
- [ ] AC-6 控制面板核心逻辑有自动化测试。
- [ ] AC-7 README 包含一键使用与故障排查说明。

## 增量需求（2026-10-19 日志与历史）

### R6 任务接收与执行日志

- Agent 领取服务端任务后必须立即记录任务 ID、项目 ID、标题与接收时间。
- 任务开始执行、成功、失败都必须产生带明确状态且有时间戳的日志。
- 不得记录 Agent Token、本地 MMKV 路径、payload 正文或其他敏感值。
- 无任务轮询不得每 5 秒重复输出相同日志，避免淹没有效任务事件。

### R7 日志时间与可读性

- Agent 日志每行使用本地时区 `YYYY-MM-DD HH:MM:SS` 时间戳与日志级别。
- 控制面板优先读取统一 Agent 日志，并按时间顺序展示最近内容。
- 兼容旧版 `agent.stdout.log` / `agent.stderr.log`，但新日志写入统一文件。

### R8 推送历史

- 本地持久化推送事件流 `work/push-history.jsonl`，重启控制面板或 Agent 后历史仍可查看。
- 同一 `jobId` 在 UI 中只展示一条最新状态记录。
- 历史字段至少包含：时间、状态、项目、标题、草稿数、任务 ID、失败原因。
- 控制面板新增「推送历史」页签，支持选择记录查看详情，并可打开历史文件。
