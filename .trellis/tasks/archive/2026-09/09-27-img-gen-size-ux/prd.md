# 生图尺寸比例选项 + 生图交互优化

## Goal

让用户在生图时能按新媒体投放场景选择**图片比例**（而非只能挑「方图/横图/竖图」三个像素值），
并把生图抽屉的交互补齐到「看得懂、错不了、能中断」的程度。

## Background（现状与硬约束，均已代码级核实）

调研结论（`explore` 子代理，2026-09-27）：

- **尺寸白名单在后端写死**：`ImageService.java:59` `ALLOWED_SIZES = {1024x1024, 1536x1024, 1024x1536}`，
  非白名单经 `normalizeSize`（`:791-796`）抛 `IllegalArgumentException` → 400。
- **前端下拉就是这 3 个值**：`AiImageDrawer.vue:12-16`（文生图）与 `:67-71`（图生图）各一份，
  label 是「方图/横图/竖图」，**不表达比例**。两 tab 共用同一 `genSize` ref（`:196`）。
- **传给下游的字段名是 `size`**（OpenAI 兼容）：文生图 JSON body（`AiImageClient.java:66`，
  `size==null` 硬编码回退 `1024x1024`）；图生图 multipart 仅非空白才 add（`:103`）。
- **下游是 axonhub 网关**（`AI_BASE_URL=https://axo.caiqz.cn`），背后模型对**非官方 WxH 的接受度仓库内无任何证据**。
- **尺寸信息已落库，不丢**：`sparkora_image_asset` 已有 `width`/`height`（px，`fillSize` 探测填）
  与 `gen_size VARCHAR(20)`（请求尺寸留档）。**本任务零 DB 迁移。**
- **展示层一律 CSS 裁切**：候选缩略图 `.cand-thumb` 与参考图缩略图 `.ref-thumb`、
  图库选择弹窗 `.ref-cell-thumb` 均 `aspect-ratio: 4/3; object-fit: cover`（`:549/:564/:578`）
  → 竖图被裁掉。存量图库同样是横图。
- **`regenerate` 用源图 `gen_size` 复现尺寸**（`ImageService.java:294/:296`），
  白名单/比例语义变化时此处须同步容错。
- **生图交互现状缺口**（读 `AiImageDrawer.vue` 确认）：
  - 生成中仅按钮 `loading` + 文字「生成中…」，**无进度、无取消**；`n=4` 时用户无法中途放弃。
  - 错误提示为字符串拼接 `ElMessage.error('生成失败：' + ...)`（`:562`），不区分超时/校验/网关错误。
  - 张数（1/2/4）与尺寸两个下拉平铺，**无比例可视化**，用户需读 label 才知道出图形状。
  - `genSize` 在生成期间可改，而请求已发出（`:445-466` 已用提交时快照 `ctx` 解决缓存串味，
    但**视觉上仍无「本次按 X 生成」的确认**）。

## Requirements

### R1 — 按比例选择出图（四档，不做精确像素）

- 提供 4 档比例，各自映射到白名单内的实际像素：
  | 比例 | 实际像素 | 实际比例 | 说明 |
  |---|---|---|---|
  | 1:1 | `1024x1024` | 1:1 | 精确 |
  | 4:3 | `1536x1024` | 3:2 | 最接近的官方横图 |
  | 3:4 | `1024x1536` | 2:3 | 最接近的官方竖图 |
  | 9:16 | `1024x1536` | 2:3 | 手机全屏，竖图近似 |
- **去重原则**：`16:9` 因与 `4:3` 同为 `1536x1024` 而**不提供**（用户已确认「去掉重复的比例档」）。
  UI 不得出现指向同一像素的第二个选项。
- **不做后处理**：不裁切、不补边。仓库现无任何图像二次加工代码，本任务不引入。
- **如实告知**：每档控件上显式标注实际像素（如 `9:16 · 实际 1024×1536`），
  不得让用户误以为拿到精确比例；`1:1` 档不显示「近似」类字样。
- **白名单不变**：`ALLOWED_SIZES` 保持 3 值，本任务只改「前端呈现语义 + 比例选择器」，不扩后端白名单。

### R2 — 生图交互优化（完整）

- **比例可视化选择器**：替代现有两个像素下拉。用可视化卡片/图形展示比例轮廓（方/横/竖），
  每项含比例名 + 实际像素；选中态明确。移动端触控目标 ≥44px。
- **生成中可取消**：**始终**提供「取消」入口（不限于 `n>1`——单张也可能卡满 300s 超时；
  `n=1` 时用次要样式以免诱导取消本会很快完成的请求）。取消用 axios `AbortController` 真正停止等待，
  并**必须如实告知**「已提交给服务端的任务可能仍会完成并入库」——
  客户端停止等待 ≠ 服务端停止处理（与 `09-27-wenyan-stale-conn` 同类事故，详见 design §3）。
- **张数与比例不联动**（本任务不加预估耗时，避免编造不可靠数字），但两者须同屏可见。
- **错误提示分层**：区分「输入校验缺失」「生成超时」「网关/模型错误」三类，
  提示须可执行（例：超时 → 建议减少张数或重试），不再只拼一个 `生成失败：`。
- **本次参数回显**：生成结果区展示「本次按 4:3（1536×1024）· 2 张生成」，
  避免生成期间改了控件却分不清产出对应哪次参数。

### R3 — 缩略图按真实比例展示

- 候选区（`.cand-thumb`）、参考图区（`.ref-thumb`）、图库选择弹窗（`.ref-cell-thumb`）
  改为按图片真实宽高比展示，竖图不再被裁成横图。
- **按 `width`/`height` 逐图适配**（`sparkora_image_asset` 入库时由 `fillSize` 探测填，`ImageService.java:821-832`），
  两列为空时回落 `4/3` 不破版。
- 网格稳定性：单元格设 `max-height` + `align-items: start`，长图不撑破网格；
  **不引 masonry 依赖**。移动端维持单列（现有 `@media max-width:768px`）。

## Acceptance Criteria

- [ ] **AC1**（R1）生图抽屉文生图/图生图两个 tab 均有比例选择器，可见 4 档：1:1、4:3、3:4、9:16；
      **不存在 16:9 选项**（与 4:3 同像素，已按决策去掉）。
- [ ] **AC2**（R1）每档标注实际像素：4:3 显示 `1536×1024`、3:4 与 9:16 显示 `1024×1536`；
      选中 1:1 时不出现「近似」类字样。
- [ ] **AC3**（R1）选 9:16 生成，产出图竖向（高 > 宽），`gen_size` 落库为 `1024x1536`，
      `width`/`height` 探测值与之一致；不触发 400。
- [ ] **AC4**（R1）后端 `ALLOWED_SIZES` 仍为 3 值（无回归）；非法 size 直传仍 400
      「不支持的尺寸: xxx」。
- [ ] **AC5**（R2）生成过程中可见取消入口（含 `n=1`）；点击后请求被中断，反馈文案**含**
      「已提交给服务端的任务可能仍会完成并入库」的如实告知。
- [ ] **AC6**（R2）取消后不再出现「已进图库」成功提示（避免误导：结果已生成但用户以为取消成功）。
- [ ] **AC7**（R2）未填 prompt 点生成 → 校验提示；断网/超时 → 错误提示可区分且含建议动作。
- [ ] **AC8**（R2）生成结果区回显本次参数（比例 + 实际像素 + 张数）。
- [ ] **AC9**（R3）生成一张竖图，候选区缩略图**竖向完整显示**，非裁切；
      网格布局在横竖混排下不错乱。
- [ ] **AC10**（R3）图库选择弹窗中的竖图（历史存量）同样按真实比例显示。
- [ ] **AC11** 回归：文生图/图生图/重生成三条链路均能正常出图；
      `npm run build` 与 `mvn -q -DskipTests compile` 通过。
- [ ] **AC12** 规格同步：`docs/spec/image.md`（§6 size 契约、§8 抽屉职责）更新比例语义与新增交互。

## Constraints

- **零 DB 迁移**：`gen_size VARCHAR(20)` 与 `width`/`height` 已够用（`1792x1024` 也才 9 字符），
  本任务不新增落库字段，故不建 `V4` 脚本。
- **不加新配置项**：比例映射是产品语义而非环境配置，**不引入 `AI_*` 配置**，
  避免为 4 个常量增加 `.env`/`.application.yml`/`AiProperties` 三处同步成本。
  若实现中确需配置化，须同步 `.env.example`（AGENTS.md 硬约定）。
- **不引入第三方依赖**：比例选择器与缩略图布局均用 Element Plus 现有组件 + CSS 实现，
  不引 Vant 等移动端框架，也不用 masonry。
- 后端注释/文档中文；前端页面用 Element Plus；移动端触控目标 ≥44px。
- 规格同步：`docs/spec/image.md`；如产生可复用前端约定，补 `.trellis/spec/frontend/index.md`。
- 前端调后端一律走 `frontend/src/api/index.js` 具名导出（`.trellis/spec/frontend/index.md:28-32`）。

## Out of Scope

- 精确比例像素（3:4→`768x1024`、9:16→`1024x1792` 等）——取决于 axonhub 下游接受度，未实测；
  方案 A 落地后如需升级，另开任务。
- 后端图像裁切/补边/长图拼接等二次加工。
- `ImageLibrary.vue` 等图库列表页的整体版式重设计（只改生图抽屉与参考图选择弹窗内缩略图）。
- 参考图按其自身比例自动推断目标比例（本次只做用户手动选比例）。
- 尺寸相关的 `imageRefCache` 跨会话持久化。

## Deferred Items（已定口径，实现时照此执行）

- **精确比例像素升级**（`3:4→768x1024`、`9:16→1024x1792` 等）：待实测 axonhub 网关对非官方 WxH 的接受度。
  升级前需一并处理「模型轮询会把所有模型试一遍导致报错难归因」（`AiImageClient.java:25/:119-123`）。
- **比例值与实际像素的持久化分离**：本次 `gen_size` 仍存像素，比例仅前端 `genRatio` ref 记忆；
  若将来需要在图库/正文里长期保留「用户意图比例」，需新增落库列（届时走 `V4+` 迁移）。
