# 图片智能应用：分类检索与自动配图（父任务）

## Goal

把图库从「人找图」升级为「系统用图」：在 09-13 标签体系之上，建立**图片主题分类 + 来源追溯**（子A），叠加**图片语义向量检索**（子B），最终支撑**文章创作配图建议**（子C，须用户批准）与**知识问答配图**（子D）。

本父任务不直接实施代码；负责需求总集、任务映射、跨子任务验收标准与最终集成核对。

## Background（09-15 勘察证据）

- 图库现状：09-13 已完成标签体系（`sparkora_image_tag`，独立关联表）+ 来源筛选 + 单图/批量打标；`source` 含 `upload`/`ai-text2img`/`ai-img2img`/`byd`/`byd-news`。
- 新闻图片现状：`source=byd-news`，157 张已入库，文件名含 `detail<newsId>`，可解析回溯；但**只有「新闻」一个标签**，无主题细分。
- **官方 `tagNames` 无细分价值**：167 条全为 `["BYD国内/新闻类型/公司新闻"]`，必须自建分类维度。
- **标题模式极规律**（已验证词表命中）：销量 45 / 出海·车展 59 / 合作签约 18 / 技术发布 22 / 里程碑 25 / 荣誉 24 / 财报ESG 6 / 车展上市 16 / 社会责任 3（有重叠，一图可多主题）。
- **新闻时间跨度 2023-01 ~ 2026-09**（2025 年 74 条、2026 年 21 条）；图库图 `created_at` 是**同步时间**（2026-09-13 全量入库），不能表达新闻发布时间——「今年销量海报」这类时间筛选必须依赖来源新闻的 `publish_date`。
- **自动配图链路目前不存在**：`VersionService.java:188` 明确要求 AI「正文不得保留原文任何图片链接…不得出现任何图片配图说明」；配图全靠预览页手动插入。`QaMessageEntity` 仅有 `citations`/`ragStatus`，无图片字段。
- **向量基建已具备**：`EmbeddingClient`（Qwen3-Embedding-8B，1024 维，OpenAI 兼容 `/v1/embeddings`）；pgvector + HNSW cosine；三张 embedding 表先例（`car_doc_embedding`/`kb_chunk_embedding`/`news_doc_embedding`），且三域**同向量空间**，`searchTopKUnified` 已跑通。

## Requirements（父级总集）

### 分类与检索（子A 承载）

- R-A1 比亚迪新闻图自动打**主题标签**（受控词表：销量/出海/合作签约/技术发布/里程碑/荣誉/财报ESG/车展上市/社会责任），基于标题规则匹配，支持一词多主题。
- R-A2 自动打**年份标签**（由来源新闻 `publish_date` 派生）。
- R-A3 图片可追溯来源新闻（`source_ref`），支持查「这张图出自哪条新闻」并跳原文。
- R-A4 图库标签筛选支持**多标签 AND**（如「主题/销量」AND「2026」）。
- R-A5 新闻知识页封面图接入图库资产（统一走图床，不再依赖官网原始 URL）。

### 语义能力（子B 承载）

- R-B1 图片文本描述向量化入库（新闻图=标题+标签；AI 图=prompt；上传图=文件名），1024 维，HNSW cosine，与现有三域同构。
- R-B2 提供按自然语言检索图片的服务接口（带相似度门槛与 top-k）。
- R-B3 图片向量可重建（幂等，先清后建，参照 KB 域 `rebuild` 先例）。

### 消费链路（子C / 子D 承载）

- R-C1 文章正文按段落锚点检索候选图片，产出**配图建议**；**所有配图写入必须由用户显式批准，系统不得自动插入**（不提供自动插入开关）。
- R-C2 复用既有 `body_image_ids` 插入机制，不新增版本-图片关联模型。
- R-C3 替换 `VersionService` 的「正文不得出现图片」旧策略为新配图链路（AI 仍不写图占位，配图由「建议 → 用户批准」补入）。
- R-D1 问答答案展示关联新闻配图（便宜路径）。
- R-D2 支持「给我看某主题图片」类语义检索问答（语义路径）。

## Non-goals（全父任务范围外）

- 不做图片**像素级内容识别/打标**（封面多为设计海报，文字标题分类 + 文本向量已足够）。
- 不做「以图搜图」（视觉相似检索），只做**以文搜图**。
- 不做独立「新闻图库」子站（复用图库页筛选）。
- 不做自动配图的人工审核工作流——但**配图建议必须用户批准后才生效**（见 R-C1；这不是「审核工作流」，而是「无批准不写入」的硬约束）。
- 不引入新的 embedding 模型或独立向量库（复用 Qwen3-Embedding-8B + pgvector）。

## 跨子任务验收标准（父级）

- [ ] 五个子任务各自 AC 全绿，且依赖顺序正确（B 在 A 之后、C 在 B 之后）。
- [ ] 全链路集成验证：新闻同步入库 → 图自动带主题+年份标签 + `source_ref` → 图库按「主题+年份」多标签 AND 筛出正确图 → 语义检索「销量海报」命中同批图 → 文章配图候选可用 / 问答展示关联配图。
- [ ] 存量数据可回溯：已入库 157 张 byd-news 图补标 + 建向量完成，重跑幂等。
- [ ] 图片向量与现有三域（car/kb/news）**同向量空间**，可被统一检索复用，无维度/模型混用。
- [ ] 零回归：不传标签的旧调用、BYD 车型图管线、既有三域检索行为不变。
- [ ] 每个子任务完成后：`mvn -q -DskipTests compile` + `npm run build` 通过；spec（`docs/s0-spec.md`）相关章节同步。
- [ ] 无 AI 生成图/上传图被新闻分类误标（分类仅作用于 `source=byd-news`）。

全部子任务归档后，由父任务执行：
1. 逐条核对上述跨子验收标准。
2. 检查 `docs/s0-spec.md` 跨章节一致性（§10 图库、§7 新闻、§6b/§6c 检索、问答章节）。
3. 检查 `.trellis/spec/` 是否沉淀了跨层约定（图片向量表与三域同空间、自动配图的候选优先策略）。
4. 输出集成核对报告；差异项回写到对应子任务或新建修复任务。
