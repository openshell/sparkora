# 修复正文泄漏事实风险审校话术(手册未提供/无法计算)

> 回链：`docs/spec/brief-generation.md`（§1 六阶段、DeepWriterService 写作契约）、`docs/spec/version-generation.md`（§3 VersionService 语义）

## Goal

消除**面向作者的内部审校话术泄漏进面向读者的文章正文**这一类缺陷。治本（停止泄漏源 + 建立读者视角契约）与兜底（落库前确定性清洗）双管齐下，使「读者永远看不到我们内部为什么缺数据」的元话语。

## Background（已核实事实，2026-10-02 线上）

### 线上样本

- 受害文章：version 44 / project 60 / brief 76《一个月46万辆、海外同比153.9%：比亚迪9月成绩单，合资品牌该怎么读？》（2026-10-02 19:27 生成，DEEP 链路）。
- 正文第 17 段（用户直接指出）：
  > 合资品牌同期在华销量的具体数据，**手册未提供**，只能提示一个方向：份额承压仍在继续。
- 正文第 25 段（第二处泄漏，用户确认即「第二个问题」）：
  > 需要说明的是，**手册未披露**其年度销量目标，**完成率无法计算**；也没有行业排名或份额数据，"全球最高之一"这类定性**不应作为结论输出**。

### 根因（三段传导，均已定位到行）

1. **简报侧生成祈使句**：`BriefService.buildDeepBriefSystemPrompt`（`BriefService.java:136`）要求「手册未覆盖的表述放入 factRisks」，schema 含 `suggestion` 字段（`:146`）。模型产出的 `suggestion` 是**写给作者的祈使指令**，brief 76 第 3 条原文：
   > 手册未提供比亚迪2026年度销量目标，也无完成进度数据。此表述**必须删除或改为「手册未披露年度目标，完成率无法计算」**
2. **写作侧整块注入**：`DeepWriterService.appendBriefSection(user, "事实风险", b.getFactRisks(), true)`（`:266`）把 `[{claim,riskLevel,suggestion}]` 整个 JSON 数组当**写作素材**注入 user prompt；模型把 `suggestion` 的祈使句改写成读者文案 → 逐字泄漏（「手册未披露…完成率无法计算」几乎照抄）。第 6 条「建议写成方向性表述…并注明缺乏同期可比数据」对应第 17 段。
3. **system prompt 自身含「手册」概念**：`DeepWriterService.java:227` 铁律 2「手册未覆盖的参数，用定性表述」+ user prompt 块头「事实手册(数值唯一来源)」（`:250`），给了模型向读者解释「手册」的语境。

### 影响面

- 线上命中统计（`content_md ~ '手册未|无法计算|未提供|不应作为结论|知识库未覆盖'`）：version **44 / 19 / 15** 三篇（19/15 为 2026-09-04 FAST 链路历史数据）。brief 侧 `fact_risks` 含元话语的：60 份中 17 份。
- 同类注入点（防御性对齐）：`VersionService.buildUserPrompt`「事实风险点（写作时注意表述，按建议弱化或标注）：%s」（`VersionService.java:296,303`）。该路径经 `ProjectVersionController.java:51-53` 对 TOPIC 恒 410，实际为**死路径**（历史 19/15 生成于 09-09 封死之前），但仍需对齐以防回归。
- 数据泄漏面：公开文章将「我们的资料没有这个数据」「单一来源待核实」暴露给读者，属对外质量问题，且暗示数据可信度缺陷。

## Requirements

- **R1（停止泄漏源）**：写作 prompt 不再注入 `factRisks.suggestion` 原文。改为**禁写断言清单**——仅取 `claim`，以「以下断言禁止在正文出现/作为事实陈述」的框架注入，保留风险防护价值。深度链路与多版本链路同步。
- **R2（读者视角契约）**：两条正文生成链路的 system prompt 增加「读者视角」铁律——正文只写给读者看；**禁止出现内部词与元话语**（手册/事实手册/简报/大纲/事实风险/未收录/未提供/无法计算/待核实/不应作为结论/据手册…）；**禁止在正文中解释「为什么没有这个数据」**——资料未覆盖的论点直接不写，或用不带来源说明的定性表达带过。
- **R3（确定性清洗兜底）**：新增可复用清洗器，落库前扫描并删除元话语句子（句级删除、段落清空则删段、压缩多余空行、不误删标题行），`log.warn` 记录被删原文。深度链路**必须**接入；多版本链路仅非仿写分支接入（仿写正文源自用户原文，过度清洗有误删风险）。
- **R4（不改既有注入文案）**：保留 user prompt 块头「事实手册(数值唯一来源):」与铁律 1~3/排版铁律逐字不变（既有测试锁定），以最小化回归面；抑制泄漏靠 R1+R2+R3 三层，而非改名。
- **R5（测试）**：清洗器正/反例单测；写作 prompt 断言 `suggestion` 文本**不出现**、禁写清单出现；system prompt 断言读者视角铁律存在。
- **R6（文档同步）**：`docs/spec/brief-generation.md`（写作 prompt 注入契约）、`docs/spec/version-generation.md`（若涉及）、`.trellis/spec/backend/ai-rag-guidelines.md`（新增「AI 生成内容不得含内部元话语」跨链路契约）。

## Constraints

- 后端单模块改动（`DeepWriterService` / `VersionService` / 新增清洗器 / 测试 / spec），**无前端改动、无 DB 迁移**。
- 清洗器必须**保守**：只删命中明确元话语模式的句子，正常数据句（如「9月销量 46.36万辆，同比 33.21%」）零误删；纯静态无状态，同 `LayoutRules` 范式。
- 中文注释与文案；不改既有对外接口契约。

## Acceptance Criteria

- [ ] AC1 深度写作 user prompt 不含 brief 76 第 3 条 suggestion 原文（「此表述必须删除或改为」「完成率无法计算」），而含禁写断言（claim）。
- [ ] AC2 深度写作 system prompt 含读者视角铁律，明确列出内部元话语黑名单与「禁止解释数据缺失」。
- [ ] AC3 清洗器对真实泄漏样本（version 44 第 17/25 段）零残留：两个泄漏句及其同段元话语全部消失，且段落结构不塌（剩余句子保留、连续空行压缩、标题不误删）。
- [ ] AC4 清洗器对正常正文零误删（含数值句、「详细参数以官方发布为准」类正常提示句、Markdown 标题与列表）。
- [ ] AC5 清洗器幂等：对自身输出再跑一次结果不变。
- [ ] AC6 `DeepWriterService` 落库内容 = 清洗后内容；数值回查（⑥ `verifyNumbers`）基于清洗后正文执行。
- [ ] AC7 既有断言零回归：`DeepWriterServicePromptTest` 中「事实手册(数值唯一来源):」、铁律 1~3、排版铁律逐字断言全部仍绿（仅「事实风险:」块断言按新契约更新）。
- [ ] AC8 `VersionService.buildUserPrompt` 不再出现「事实风险点」与 factRisks 原文（死路径防御性对齐）。
- [ ] AC9 `mvn test` 全绿；`mvn -q -DskipTests compile` 通过。

## Out of Scope

- **存量正文回溯清洗**：version 44 / 19 / 15 的既有正文不做批量改写（改写生产数据属不可逆副作用，且编辑页已支持人工改正文）。若需要，另开一次性人工确认脚本。
- 简报侧 `suggestion` 文案风格改造（简报是给作者看的，说「手册未提供」是正确的，不改）。
- `AI_MODEL` 换非 reasoning 模型、axonhub 路由稳定性（运维，另线）。
- 数值回查把派生占比（如 61,379/463,561=13.2%）误判 high 风险、目标字数 500 实际产出 1327 字——已识别但属独立问题，另开任务。
