# 重复配图防御:已有插图锚点跳过与跨锚点同图去重

## Goal

生成建议时跳过已有插图的锚点,并对跨锚点候选同图去重,消除「同段插两份图」「同图重复推荐」两类缺陷(评审 P1b)。

## Requirements

- **R1 已有插图锚点不产建议**:锚点所在标题节(该 heading 行到下一同级/更高级标题之间的原文,含节内任意行)存在 markdown 图片语法(`![](…)`),即视为已配图——该锚点不出现在建议结果中(与「无候选锚点不出现」同语义)。不做 UI 标注;围栏(``` ` ~~~)内的图片语法不判定(与 extractText 丢弃围栏内容一致)。
- **R2 跨锚点同图去重**:单次 suggest 调用内,同一张图只出现在最先(相似度最高)命中的锚点组,后续锚点组不再出现该图。
- **R3 已登记正文插图排除**:当前版本 `sparkora_article_version_image` 已关联的图片 id 不进入任何新锚点组的候选(无论其图片语法是否还在正文 markdown 中)。封面(`cover_image_id`)不参与判定。
- **R4 契约与硬约束不变**:接口字段不变(仅候选内容收窄);suggest 仍零副作用;dismiss/指纹语义不变;**不注入 ImageService 写路径**——R3 只读关联表,经由只读 mapper 实现,类注释同步更新。

## Acceptance Criteria

- [ ] 单测:AnchorExtractor 锚点级图片判定——标题行后紧跟图片段 / 节中间插图 / 围栏内图片语法不误判 / 无图 false
- [ ] 单测:suggest——含图锚点被跳过;同图跨锚点只出现一组;已登记关联图不出现
- [ ] `mvn -q -DskipTests compile` + `mvn test` 全绿
- [ ] `docs/spec/image.md` §7.2 过滤规则与接口行为描述同步更新
- [ ] 真机(项目 65 容器环境):在某段插图后重新生成建议 → 该段不再出现在候选;已插图不再被后续段落推荐;采纳流程不受影响

## Non-goals

- 锚点句级分块检索(中期另行立项)
- 前端 UI 任何改动(「已有插图」不出提示,空态文案已有解释)
- 封面参与判定、建议结果缓存、每段多图偏好
