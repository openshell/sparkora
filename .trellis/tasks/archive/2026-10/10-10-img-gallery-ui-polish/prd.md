# PRD：图库 UI 优化（按钮留白 + 预览交互 + 设计评审收敛）

任务目录：`.trellis/tasks/10-10-img-gallery-ui-polish/`
类型：复杂任务（交互重设计）· 前端 only · 单任务（无父子拆分）

## 1. 背景与问题

图库页（`/images`）用户反馈三类问题（2026-10-10）：

1. **按钮左侧留白过多**：卡片 hover 层内的 `el-button size="small" text` 按钮自带 ~11px 水平内边距且无底色，三个文本按钮排一行视觉上有大段空白；工具条「批量管理」用了 `text + plain + danger` 叠加，呈现「带边框但内部留白异常」的异形样式（`ImageLibraryToolbar.vue:57`）。
2. **预览难触发**：卡片 hover 层（`ImageCard.vue:117-118`）hover 时 `pointer-events: auto`，内含 5~7 行要素（文件名/副行/相关度/来源追溯/生成模型/标签/操作按钮），而预览触发完全依赖点击落在 `el-image` 上——要素越多的图，遮罩越大，越点不进预览，交互自相矛盾。
3. **整体设计评审**：用户要求借机评审图库设计并优化。已识别：工具条单行 10 控件无视觉分隔；连续预览初始索引走 `pageOriginUrls.indexOf(originUrl(img))`，URL 重复时定位错位（小缺陷）；hover 层元数据与预览详情职责混杂。

## 2. 用户决策（2026-10-10 会话确认）

- 修复方向：**优化列表 hover 层显示效果**（瘦身 hover 层，恢复「点卡片≈看图」的直觉），而非仅加显式预览按钮。
- 用户建议并采纳：**全屏预览（看大图）时展示图片更详细信息**——列表层职责收窄为「浏览/筛选/快速操作」，详情层职责收敛到全屏预览。

## 3. 需求

### R1 按钮留白修正
- 卡片 hover 层操作按钮（编辑标签/重生成/删除）：水平内边距收敛（`padding: 4px 2px` 级别），消除大段视觉空白。
- 工具条「批量管理」：去掉 `text + plain` 异形叠加，改为干净的 `text type="danger"`。
- 全库审计其余 `text + plain` 组合按钮，同类问题一并修（仅图库域内）。

### R2 hover 层瘦身 + 整卡点击预览
- **hover 层仅保留**：文件名（1 行）、副行（来源 · 项目 · 尺寸）、标签行（点击=按标签筛选）、操作按钮行。其余元数据（相关度原文、来源追溯、生成模型/尺寸）全部移出列表层。
- **语义搜索模式**：相关度分数改为卡片角标（极轻量、非交互），分数解释原文下沉到预览层。
- **整卡可点**：点卡片任意位置 = 打开全屏预览（交互元素——标签/来源链接/操作按钮/勾选框——各自 `@click.stop` 阻断）。
- hover 层非交互行 `pointer-events: none`，鼠标穿透不吞点击；hover 显隐仍以 `:hover` / `:focus-within` 驱动。

### R3 全屏预览详情面板
- 看图体验升级为「大图 + 右侧信息面板」：连续浏览（当前页原图、左右箭头/键盘）保留。
- 面板展示：文件名、来源、项目、宽×高、创建人 · 时间、生成模型 · 规格（AI 图）、**生成 prompt 全文**、标签、语义相关度分数 · 命中原文（语义模式）、来源追溯（新闻标题·日期，可点击跳原文）。
- 字段空值容错（语义检索命中是 `ImageSearchHit` 子集：无 `projectId` 等字段，不得臆断「全局」）。
- 原图 URL 约定不破坏：预览只用 `url`，`thumbUrl` 仅网格缩略（spec 硬约定）。
- 面板可关闭（面板显隐切换），关闭后剩纯看图模式（不损失 EP viewer 内置缩放/旋转/下载）。

### R4 评审项小改（低风险顺带修）
- 工具条「主操作组」与「浏览控制组」之间增加视觉分隔（divider）。
- 预览定位改为按 v-for 索引直传，废除 `indexOf(url)` 消除重复 URL 错位。

## 4. 非目标（明确不做）

- 不改后端接口与数据结构（所有字段已存在）。
- 不做全屏预览内编辑（编辑标签/删除/重生成仍留在列表 hover 层操作）。
- 不做选择模式下的大图预览（选择模式点击=勾选，维持现状；将来可加放大镜角标，另行任务）。
- 不改「图库空态/分页/筛选 chip/批量管理」既有结构（仅按钮样式微调）。
- 不引入新 UI 框架；不引 masonry 等重排版方案。

## 5. 验收标准

- AC-1 hover 层操作按钮行无大段水平留白；「批量管理」为正常样式；全图库域无残留 `text + plain` 叠加按钮。
- AC-2 点卡片任意非交互区域（含 hover 层文字行）都打开全屏预览；点标签=筛选、点来源=跳原文、点操作按钮=对应动作、选择模式点卡片=勾选，均不被预览劫持。
- AC-3 hover 层要素收敛到 4 组（文件名/副行/标签/操作），语义模式相关度以角标呈现。
- AC-4 全屏预览右面板按 R3 字段清单展示，字段缺失时隐藏对应行不臆断；面板可关闭；左右切换时面板信息跟随当前图。
- AC-5 连续预览仍为当前页原图序列（`url`），首张定位正确（含重名 URL 场景由索引直传保证）。
- AC-6 `npm run build` 通过；`npm run test`（Playwright 门禁）通过——图库页视觉基线按 `--update-snapshots` 重录像素变化部分。
- AC-7 实测回归清单：明暗 2 主题 × 图库浏览态 + 语义搜索态 + 选择模式 + 全屏预览（含详情面板开合）。

## 6. 假设与风险

- `el-image-viewer`（EP 2.8）暴露 `@switch(newIndex)`/`@close`，可作单实例宿主 + 自绘信息面板的外挂联动；若自动引入解析失败，显式 `import { ElImageViewer } from 'element-plus'` 兜底（spec「动态组件必须显式 import」精神）。
- 视觉回归门禁涉及图库基线，需按 spec 流程重录。
- 交互范式变化（预览从「点图」变「点卡片」）对用户习惯是改善但需实测确认无 hover 闪烁（面板渐变过渡保留）。
