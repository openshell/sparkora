# 文章创作自动配图（子C）

## Goal

文章正文生成后，按段落语义自动检索匹配的图库图片，产出**配图建议**；**所有配图写入都必须由用户显式批准**，系统不得自动插入。把图库从「手动选图」升级为「系统建议、用户定夺」。

## Dependencies

- **前置**：`09-15-img-semantic-search`（子B）必须完成——本任务消费其 `searchImages(queryText, topK, minScore, tags)` 检索能力。
- 间接依赖子A（图片标签与来源追溯，子B 已依赖）。
- 若子B 未完成，本任务无检索能力可用，**不得提前开始**。

## Background（09-15 勘察）

- **当前链路禁止图片**：`VersionService.java:188` prompt 明确要求「不得保留原文任何图片链接、图注、配图说明，正文不得出现任何图片占位或「配图」字样」；`:269` 还有残留占位行剔除逻辑。即**自动配图链路从不存在**，配图全靠预览页手动插入。
- 已有版本-图片关联：`sparkora_article_version.cover_image_id`（封面）+ `body_image_ids`（正文插图 id 逗号分隔，有序），由 `ImageService.setCover`/`modifyBodyImage` 维护（幂等）。
- 预览页 `StepPreview.vue` 配图面板已支持从图库插入（分页接口 + 筛选 + 触底加载）与 AI 生图。
- 项目已关联车型时可做 RAG 检索（`searchTopKUnified`），说明「生成时调用检索」的编排范式已存在。

## Requirements

### R1 段落锚点切分

- 从版本正文 Markdown 中提取**可配图锚点**：按二级/三级标题或段落边界切分，得到 `[{anchorIndex, headingPath, text}]`。
- 跳过明显不需配图的段落（如纯列表、引用块、过短段落 < N 字）；可配图段落数设上限（如 ≤5），避免配图过密。

### R2 逐锚点语义检索

- 对每个锚点文本调 `ImageService.searchImages(anchorText, topK=5, minScore=门槛, tags=项目主题标签?)`（子B 能力）。
- 门槛以下无候选则该锚点不配图。
- 可选：用版本/项目主题作为检索 query 的一部分提升相关性。

### R3 配图建议（必须用户批准，无自动插入）

- **硬约束：系统只产出建议，绝不自动写入 `body_image_ids`。** 配图进入正文的唯一路径是用户显式操作（单张采用 / 整组采用）。理由：插错图比不插图更糟，且配图直接影响发布内容的正确性。
- **不提供自动插入开关**：不存在 `AUTO_ILLUSTRATE_ENABLED` 之类的自动写入能力，从设计上排除「无人值守自动配图」。
- 预览页配图面板新增「智能配图建议」区：按锚点分组的候选图，支持单张「插入到此段」、整组「全部采用」、忽略/丢弃该建议组。
- 建议的生成（检索）可自动触发，**但建议本身只是待批准状态**，不改变正文与 `body_image_ids`。
- 用户「忽略」的建议应被记住（不再重复推荐同一锚点的该批候选），避免反复打扰。

### R4 插入复用既有机制

- 采用后调既有 `ImageService.modifyBodyImage(projectId, imageId, "add")` 写入 `body_image_ids`，不新增关联模型。
- 正文内的图片引用格式沿用预览/发布既有约定（frontmatter `cover` 用于封面；正文插图由 `body_image_ids` + 渲染层插入）。

### R5 替换「禁止图片」旧策略

- `VersionService` 的 prompt 约束与残留占位剔除逻辑需与新链路协调：**正文仍不由 AI 生成图片占位**（避免 AI 编造图 URL），配图由系统在生成后基于正文语义补入——即保留「AI 不写图」约束，但新增「系统补图」链路。二者不冲突，需在 design.md 明确边界。
- 若最终采用「AI 写占位标记 + 系统替换」方案，需同步改 prompt 与剔除逻辑；**推荐保持 AI 不写图**，改动最小。

### R6 可追溯与可关闭

- 生成建议是**幂等可重算**的（同一版本同一正文重算结果稳定，除非图片库/模型变化）。
- 提供关闭能力：项目/全局开关关闭后不产生建议（关闭的是「建议」的生成，与 R3 的「禁止自动写入」是两件事）。

## Non-goals

- **不做自动插入配图**（R3 硬约束）：任何形式的无用户确认写入都不在本任务范围。
- 不做图片排版/尺寸适配策略（沿用既有渲染）。
- 不做 AI 生成配图（AI 生图已在预览页手动提供）。
- 不做自动配图的视觉审美排序（只按语义相似度）。
- 不改封面图逻辑（封面仍由用户选定或既有 AI 流程）。
- 不引入新模型/新向量库。

## Acceptance Criteria

- [ ] 从版本正文可提取可配图锚点（标题/段落），数量受上限约束，纯列表/过短段落被跳过。
- [ ] 每个锚点能调子B 检索得到建议候选（含分数、缩略图、标签、来源），门槛以下自动无候选。
- [ ] 预览页展示按锚点分组的「智能配图建议」；支持单张采用、整组采用、忽略。
- [ ] **生成建议后 `body_image_ids` 与正文均未被修改**（建议本身零副作用）；只有用户点击采用才写入。
- [ ] **代码与配置中不存在自动写入配图的能力**（无自动插入开关；不因高分数而自动插入）。
- [ ] 采用后 `body_image_ids` 正确写入且幂等（重复采用同一张不重复）。
- [ ] 被「忽略」的建议组不再对同一锚点重复推荐。
- [ ] 建议可重算且结果稳定；无候选的锚点不报错。
- [ ] AI 仍不生成图片占位（正文无编造图 URL）；采用后的配图与既有渲染/发布链路兼容，预览与发布所见图即所得。
- [ ] 关闭建议开关后不产生建议。
- [ ] 权限：读建议三角色；采用（写 `body_image_ids`）ADMIN/EDITOR。
- [ ] 零回归：新功能未使用时，现有版本生成、预览、发布、手动配图行为完全不变。
- [ ] `mvn -q -DskipTests compile` 与 `npm run build` 通过；`docs/s0-spec.md` §10/§11 同步配图建议链路。
